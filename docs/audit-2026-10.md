# Audit, October 2026: the language, the runtime, the widgets and the IDE against the field

**Status: open.** An independent audit, written on 2026-10-10 without taking the
repository's own documents on trust: every claim was checked against the code,
and where it could be, against a probe. Each finding has an id so the work can
be picked up one at a time; when one is answered, mark it here and follow the
rule that governs `docs/issues/` -- the answer goes where the reader looks, and
this file keeps only what is still owed.

How each finding was established, in the **Evidence** line:

- **probe** -- reproduced with a console project or on a virtual display
  (`tests/try.sh`), and the output is quoted;
- **code** -- read in the source, at the place named; not run;
- **claimed** -- a number the repository states and the audit did not re-measure.

The IDE half (section 5) is code reading only: the IDE was not started.

Severity is **High** (blocks a class of application, or a silent wrong answer),
**Medium** (costs real work or surprises) and **Low**.

## 1. Concrete defects -- fix first

These are bugs rather than gaps, and each is small.

### D1. `import()` compiles, says nothing, and aborts the process at exit -- High
- **What.** A dynamic `import()` is not refused by the parser, the way patch 5
  refuses `async`. It builds a promise-shaped object that, with no
  `JS_AddIntrinsicPromise`, is never collected -- the same mechanism patch 5's
  note describes.
- **Evidence (probe).** `function Main(){ try { import("./x.js"); } catch(e){} print("done"); }`
  prints `done`, then `JS_FreeRuntime: Assertion 'list_empty(&rt->gc_obj_list)' failed`,
  exit **134**. `Application.CheckSource` answers `null` for the same source.
- **Direction.** Refuse `import(` in the parser beside the `async` guards, with a
  message and a column; add the spelling to `testCuratedLanguage`. Stage 1 of
  [plans/modules-plan.md](plans/modules-plan.md).
- **Done (branch `modules`).** Fork patch 13 refuses `import(` at the word,
  and a module's top-level `await` beside it; `CheckSource` now answers the
  probe's source with a `SyntaxError` at its column.

### D2. An uncaught error in a callback of a `main` project exits 0 -- High
- **What.** The same `ReferenceError` exits 1 when thrown in `Main` and 0 when
  thrown from a `Timer` callback.
- **Evidence (probe).** `function Main(){ Timer.After(10, () => nope()); }` prints
  the traceback and exits **0**.
- **Impact.** Console projects are the runner, build steps and CI tools; a
  failure there reads as success.
- **Direction.** Record that an uncaught error happened and make the console
  loop's exit status non-zero unless `Application.Quit(code)` said otherwise.
- **Done.** `bta_dump_error` marks the application (`BtaApp.uncaught`, set at the
  one place every uncaught error ends) and `run_console` answers `1` for a run
  that reported one unless `Application.Quit(code)` said otherwise;
  `tests/smoke`'s `testConsoleExit` runs child console projects and holds the
  three statuses (1 for the uncaught error, 7 for a program that quits after
  one, 0 for a program with nothing to report). See *An uncaught error is a
  failing status* in [architecture.md](architecture.md).

### D3. `TableView.Add` is quadratic -- High
- **Evidence (probe, Xvfb).** 10 000 rows 0.65 s, 20 000 rows 2.3 s, 40 000 rows
  17.4 s, in a window or not. `perf`: time is in
  `gtk_list_item_manager_model_items_changed_cb` / `gtk_rb_tree_node_get_next`.
  `table_add` (`runtime/src/bta_table.c`, ~2162) appends one item per call and
  each append raises `items-changed`. `TreeView` with 10 000 nodes: 644 ms.
- **Contrast.** The on-demand mode (`Count = 1e6`) is 19 ms; `SortBy` of 20 000
  rows 15 ms; `Clear` instant.
- **Direction.** A batch verb (rows in, one `g_list_store_splice`), or coalescing
  appends made in one turn. The ordinary road -- fill a table from a query -- is
  exactly the one that hangs.
- **Done.** `AddRows(rows)` -- the whole batch is built first, so a refused
  value adds none of it, and it enters the store through one
  `g_list_store_splice`; refused on a tree, and it clears an on-demand `Count`
  as one `Add` does. Measured on the review's machine: 10 000/20 000/40 000
  rows in 25/30/42 ms, where the loop was 0.63 s/2.8 s/7.4 s. `tests/widgets`'
  `TableBatch` holds the semantics and a seconds-wide bound the loop fails.
  See *A `GListStore` append raises `items-changed`* in
  [agents/tables.md](agents/tables.md).

### D4. `Decimal` equality compares identity -- Medium
- **Evidence (probe).** `new Decimal("1") == new Decimal("1.0")` is `false`;
  `a <= b && a >= b` is `true`. The arithmetic hook (`runtime/src/bta_decimal.c`,
  ~590) covers ADD..GTE and not equality, and the class table (~925-952) has no
  `Equals`.
- **Impact.** `if (total == expected)` fails silently in exactly the
  application `Decimal` exists for.
- **Direction.** At least `Decimal.Equals(a, b)` / `a.Equals(b)`; whether `==`
  can be hooked is a fork question (a seventh operator in patch 1).
- **Done.** `Equals(other)` on a decimal -- exact, across scales, and reading a
  number or machine text as the operators do -- with the identity of `==`
  asserted beside it in `tests/widgets`' `Decimal`, which goes red without the
  member. Hooking `==` stays the fork question this finding named and was not
  taken; the trap and the method are in *A decimal is an object* in
  [agents/data.md](agents/data.md).

### D5. Error messages carry GLib's translated text -- Medium
- **Evidence (probe).** `File.Load("/nonexistent")` ->
  *"…Falló al abrir el archivo «/nonexistent»: No existe el fichero…"*;
  `Exec.Wait(["/nonexistent"])` -> *"Falló al ejecutar el proceso hijo…"*;
  `Http.GetWait` -> *"cannot reach …: Se canceló la operación"*.
- **Impact.** The rule AGENTS.md states for `Gzip` ("never quote a GLib message
  in an error") is not applied elsewhere: an error reads differently per
  machine, cannot be matched by a program, and does not paste into a report.
- **Direction.** Sentences of our own built from the `GError` domain and code,
  file by file; `err->message` only behind them, if at all.

### D6. `Application.Replacements` answered `undefined` -- Low (unconfirmed)
- **Evidence (probe, one run).** `.slice` on it failed, while the comment near
  `runtime/src/bta_runtime.c:174` describes it as published. Re-check before
  acting: it may be the probe.

### D7. AGENTS.md contradicts itself about `DatePicker` -- Low
- **Evidence (probe).** `d.Value = ""` reads back `""`: the empty state exists
  (`bta-date-empty`). *Two widget limits that leak into a shape* still says a
  `DatePicker` has none, and that `examples/clients` declares `Since` as
  `required` because of it.
- **Direction.** Correct the note, and decide whether `examples/clients` keeps
  `required` for a reason of its own.

## 2. The language

### L1. One global scope, no modules -- High
- **Evidence (probe).** `A.js` and `B.js` both declaring `function helper()`:
  `helper()` is B's, silently. The same `const` in two files: the program does
  not start (`SyntaxError: redeclaration of 'LIMIT'`). `Namespace()`
  (`runtime/js/rad.js`, ~1084) publishes an object and does not scope the file:
  top-level `const`s stay global (`ide/modules/Designer.js` declares `GRID` and
  `MIN_SIZE` under `Namespace("Ide")`). Libraries share the scope too.
- **Impact.** A large project or two third-party libraries collide either in
  silence (functions) or fatally (`const`, `class`).
- **Field.** Delphi/Lazarus units, Gambas one class per file, .NET namespaces
  and assemblies, Python and ES modules.
- **Plan.** [plans/modules-plan.md](plans/modules-plan.md).
- **Done (branch `modules`).** A file that says `export` is a module: the rest
  of its names are its own, so two files' private `helper` or `LIMIT` live side
  by side (a library's too -- `lib/markdown` is one). What a module exports still
  reaches every file without an import; a name two modules export is refused
  at load where a file uses it with no `import`, naming the file and the line
  (fork patches 16 and 17), and an `import` chooses. The IDE moved off
  `Namespace("Ide")` onto modules; whether `Namespace` itself stays is
  [plans/namespace-plan.md](plans/namespace-plan.md).

### L2. Asynchrony is callbacks only -- High
- No `async`, no `Promise` (both by decision), no blocking `MsgBox` either. A
  sequence of I/O is nested callbacks or a `*Wait` that freezes the window (see
  R6). `docs/plans/async-plan.md` is the open answer.
- **Field.** Gambas, VB6, Delphi and Xojo answer with blocking modal dialogs;
  .NET, Python and Electron with `await`. Bintana has neither.

### L3. No static checking beyond the parser -- Medium
- `CheckSource` finds syntax only; `undefinedThing.foo()` passes. A misspelt
  property on a plain object or a record is accepted. `--strict` covers
  controls only. In favour: every source is evaluated strict, so an undeclared
  assignment throws.
- **Field.** Every compiled competitor types; Python and JS have mypy/pyright and
  TypeScript.

### L4. A `Task` sees only its own file, and messages are plain data -- Medium
- **Evidence (probe).** A helper in `Util.js`, listed in `sources`, is a
  `ReferenceError` inside the worker. `Date`, functions, `Bytes` and class
  instances do not cross. No `Exec`, `Timer`, `Dialog`, `Settings` in a worker
  (`runtime/src/bta_task.c`, ~1210-1217). `examples/sheets` duplicates helpers
  for this reason.
- **Direction.** Let a task class declare the files it needs, or load the
  project's non-form sources into the worker.

### L5. Standard calls give a wrong answer in silence -- Medium
- `sort()` without a comparator orders `Bruno,Zapata,Álvarez,ñu`;
  `toLocaleString()` ignores the locale (`1234567.891`); no `Intl`.
  `localeCompare` is refused with a pointer, which is right -- the others are
  not refused and cannot be.
- `Locale.Date(new Date(0))` is `"31/12/69"` (two-digit year from `%x`) while
  `Date.toLocaleDateString()` is US order on a Spanish desktop: two answers.
- **Direction.** A four-digit-year default for `Locale.Date`; documentation of
  the silent ones where an author looks first.

### L6. The curation breaks JavaScript habits, and the hint is lost in a `catch` -- Low
- No `Object.*`, `setTimeout`, `console`, `new RegExp`, TypedArrays,
  `structuredClone`. The replacement messages are good but only appear on an
  *uncaught* error; the same `ReferenceError` caught by a `try` carries none.
  Existing JS cannot be pasted in and npm is out of reach.

### L7. `Object.prototype` is writable and there is no defence -- Low
- `Object.prototype.zz = 1` makes every `for...in` recite `zz`; `freeze`/`seal`
  went with `Object`. Only the project and its libraries can do it.

### L8. Interpreter only -- Low/Medium
- Debug `fib(27)` ~64 ms (probe). Release numbers in `docs/testing.md` are
  claimed: on par with or ahead of CPython on floating point, up to 1.6x behind
  elsewhere. Enough for forms and CRUD, weak for bulk data on the UI thread.
  `docs/plans/interpreter-plan.md` is the open answer.

## 3. The runtime library

### R1. SQLite is the only database, and `Query` has no cursor -- High
- `Database` publishes `Sqlite` alone (`runtime/src/bta_database.c` mentions a
  future `Postgres`). `Query` returns every row in an array (the cursor is stage
  3 of `docs/plans/data-plan.md`).
- **Field.** FireDAC, SQLdb/Zeos, Gambas `gb.db` (MySQL, PostgreSQL, ODBC), Xojo,
  ADO.NET, QtSql. Client-server business applications -- the RAD niche -- are
  ruled out.
- **Direction.** `Database.Postgres` on libpq first; the `Connection` base class
  already exists for it.

### R2. No accessibility API -- High
- No `gtk_accessible_*` call in `runtime/src`; nothing in `api.json` for an
  accessible name, role, description or *labelled by*. Mnemonics are refused on
  purpose (`docs/llm/issues.md`). Only `Tooltip`, `TabIndex` and `FocusNext`.
- **Impact.** Applications cannot meet Section 508 / EN 301 549, which public
  sector and banking procurement ask for; Orca reads unnamed controls.
- **Direction.** `AccessibleName`/`AccessibleDescription` on `Widget`, a
  `Label.For` relation (`GTK_ACCESSIBLE_RELATION_LABELLED_BY`), and revisiting
  mnemonics.

### R3. Networking and IPC stop at HTTP and `Exec` -- Medium/High
- Missing: TCP/UDP sockets, WebSocket, serial ports, D-Bus, SMTP, single
  instance (`G_APPLICATION_NON_UNIQUE` in `runtime/src/bta_runtime.c`, ~3138, so
  no forwarding of arguments to a running instance), a clicked notification
  reaching the program. Tray and global hotkeys are GTK4's absence.
- **Impact.** Point of sale (fiscal printers, scales), legacy socket
  integration, real-time.
- **Field.** Gambas `gb.net`/`gb.dbus`/SerialPort, Lazarus Synapse/LNet,
  Qt Network/SerialPort/DBus, Electron `net`/`ws`/single-instance lock.

### R4. `Http.Server` answers inside the handler, and does not limit the body -- Medium
- A handler that returns without `Answer` gets a 500 and a later `Answer`
  throws (`runtime/src/bta_http.c`, ~4046-4051): a handler cannot wait on
  another request, a `Task` or an `Exec` -- the very callback style L2 imposes.
  The body is flattened whole (`soup_message_body_flatten`, ~4008-4013) with no
  size limit. Loopback is the default, which mitigates it; `"any"` does not.
- **Direction.** `soup_server_message_pause`/`unpause` behind a deferred
  answer; a `MaxBody` option with a sane default.

### R5. Windows untested on a desktop, macOS not started -- Medium
- The `windows` CI job builds, runs `tests/api.sh` and packs a zip and an NSIS
  installer; the windowed suite does not run there, and
  `docs/plans/portability-plan.md` says the zip is unverified. Missing on
  Windows: `Terminal`, `Keyring`, `Printer.Names`/`Default`, `Exec`'s `Control`.
  `docs/plans/macos-plan.md`: not started.

### R6. `*Wait` verbs block the window with no default limit -- Medium
- `Exec.Wait` and the seven `Http.*Wait` iterate a private context; without
  `Timeout` they wait forever (`runtime/src/bta_http.c`, ~2675: timeout 0 is
  infinite). With a timeout they behave (probe: `Exec.Wait(["sleep","3"],
  {Timeout:300})` -> `[-1]` in 302 ms).
- **Direction.** A finite default timeout on the blocking spellings.

### R7. Deployment -- Medium
- Flatpak (via `lib/package`, command line), a tarball and an NSIS installer. No
  AppImage, deb or rpm; no signing; no updates. Sources ship in the clear
  (`docs/plans/bundle-plan.md` is a plan).

### R8. Pieces a business desktop application expects -- Medium
- No symmetric encryption (AES) nor an encrypted database (`Keyring` is secrets
  only); no PDF reading; print preview delegated to Evince/Papers and failing
  without them; no image object to scale/crop/rotate (`Probe.Image` is size
  only); `Dialog.OpenFile` has no multiple selection; no global font dialog;
  `Message` has no question/confirm (it is `lib/dialog`).

### R9. Small inconsistencies -- Low
- `File.Join("/srv/root", "../../etc/passwd")` is not normalised; `File.Within`
  exists and has to be remembered. `Table` refuses `Id` against `id` loudly
  (right), which makes `Naming` a line every SQL record needs.

## 4. Widgets

### W1. The data grid is far below a business application's -- High
- **Answered: cell kinds.** A column's `Editor` is `Text`, `Number`, `Date`,
  `Check`, `Combo` or `Custom`, a row can shut its cell (`SetEditable`, `Data`'s
  `Editable: false`), `CellEditor` adjusts or refuses each edit, and the
  designer's column dialog edits all of it -- see *A table cell's editors* in
  AGENTS.md and `examples/plan`. Per-cell validation is `CellEdit`'s veto and
  its string answer.
- **Still owed.** No filter, frozen columns, hiding or reordering
  (`set_reorderable(FALSE)`), grouping, totals row, range copy/paste. In
  favour: stable natural sort with a comparator, on-demand mode, tree mode,
  links, `HeaderMenu`.
- **Field.** DBGrid (Delphi/Lazarus), DataGridView, Gambas GridView, and the
  DevExpress/AG-Grid class.
- **Direction, in order.** D3 first; hide/reorder columns; filter.

### W2. No data binding -- High
- Nothing binds a `Record` field to a control: no navigator, no invalid-control
  marking (`Validate()` returns strings; nothing like an ErrorProvider). Every
  create/read/update form is written field by field, both ways.
- **Field.** TDataSource/DBEdit, BindingSource + ErrorProvider, WPF binding,
  Gambas DataSource/DataBrowser.
- **Direction.** `docs/plans/data-plan.md` is the place; the record already
  knows its fields, the form its controls.

### W3. Business controls missing -- Medium
- Masked input (tax id, phone); autocompletion in a `TextBox`/`ComboBox` (an
  editable combo is `ISSUE-editable-combo`); tag input; rich text editing; a web
  view (no WebKitGTK); a PDF viewer; status bar, toolbar, docking, splash,
  wizard, accordion, scheduler as controls; a `PropertyGrid` for applications.
  In favour: `DecimalBox` is exact and locale-aware (probe: `1234.567` ->
  `1234.57`, text `1234,57`).

### W4. `ComboBox` has no empty state -- Medium
- **Evidence (probe).** After `Items`, `Index` is 0; `Index = -1` leaves it at 0;
  `Text = ""` is refused. An optional field needs a placeholder row translated
  on every read and write, and a combo of prose must be read by `Index`.

### W5. The two layout models are powerful and fragile -- Medium
- `BtaFixed` anchors by alignment against the declared size; `Grid` is
  auto-flow only (`Columns` + `ColumnSpan`, no explicit row/column, no
  `RowSpan` -- `runtime/src/bta_layout.c`, ~1477). The traps AGENTS.md lists are
  the cost: `MinWidth` inert off `Fill`, `Width` a minimum in a box, a hidden
  page latching the wrong design size, translations pushing windows. A VB or
  Delphi author will draw everything in `Fixed` and get forms that break on
  resize or translation.
- **Direction.** Explicit grid placement and `RowSpan`; a designer that
  nudges a form of regions towards boxes.

### W6. No right-to-left -- Medium
- `BtaFixed` does not mirror X; icon lookups pass `GTK_TEXT_DIR_LTR`
  (`runtime/src/bta_controls.c`, ~2019, ~2089); nothing asks the direction.
  Boxes mirror on their own; `Fixed` forms do not.

### W7. Smaller points -- Low
- An application cannot force light or dark (only the setting is read).
- A `RowList` cannot drag inside itself (the list box claims the gesture).
- A property declared in a `.form` raises its event before sibling controls
  exist.

## 5. The IDE (code reading only)

### I1. Editor ergonomics -- High
- No folding, multiple cursors, snippets, minimap or formatter (`bta_editor.c`
  sets auto-indent and little else; *Tidy* sorts files, it does not format).
  GtkSourceView 5 has `GtkSourceMap` and snippets unused.
- Syntax is checked on save only (`ide/modules/Live.js`, header); typing checks
  names of controls and events. A debounced check that skips the token under
  the cursor -- the rule `Live.js` already has -- would do.

### I2. No non-visual components on the form -- High
- The palette lists widgets (`ide/modules/Palette.js`, ~52-62). A `Timer`,
  `Http`, connection or `Exec` cannot be dropped and configured in the property
  grid; `Action` only through its dialog. This is the gesture Delphi, Lazarus,
  Gambas and Xojo are built around.
- **Direction.** A tray of non-visual objects in the `.form` (a sibling of
  `actions`), each a runtime class answering `PropertyNames`.

### I3. No database tools -- High
- No schema browser, query console, query designer or data module. The runtime
  has `Table`, `Record` and SQLite; the IDE does not help use them.

### I4. No report designer -- Medium
- `lib/report` is defined in code or properties; on the canvas it is a grey
  stand-in. Lazarus (LazReport), Delphi (FastReport) and Gambas have one.

### I5. No test runner for user projects -- Medium
- No template, launch configuration or results view for tests.

### I6. Debugger values are flat -- Medium
- `ide/modules/Debugger.js` (~520-575) shows each value as an ellipsised
  `Label`: no tree for objects and arrays. No `Task` debugging, data or
  hit-count breakpoints, edit and continue.

### I7. Rename stops at top-level declarations -- Medium
- `ide/modules/Refactor.js` leaves out `Variable` and `Static`; locals and
  parameters, which the parser already scopes (patch 9), cannot be renamed.

### I8. Packaging leaves the IDE at the last step -- Medium
- `ide/modules/Exporter.js` writes a `.tar`; Windows installer and user install
  exist; Flatpak is `tools/pack.sh` only.

### I9. F1 depends on another repository -- Medium
- `ide/forms/HelpForm.js` (~37-50) looks for `docs/reference` in a sibling
  `bintana-docs` or `share/doc`; a checkout or package without it opens nothing.
- **Direction.** Ship the reference with the IDE, or fall back to the web.

### I10. Smaller gaps -- Low/Medium
- Git: no blame, stash, merge or conflict resolution, no amend or hunk staging;
  commit is a single `-m` (`ide/modules/Git.js`, ~574).
- Alignment: no align centres or centre in form; the 4 px grid is fixed and
  invisible (`ide/modules/Designer.js`, ~40).
- No IDE extensibility; templates are *a form* or *a function*; no explicit
  accessibility; no profiler launch (the runtime has `--profile`).
- Undo keeps up to 200 JSON snapshots of the whole tree per edit; not measured
  on a large form.

## 6. Against the field

Versions as found on 2026-10-10. Prices for Qt, PureBasic and B4J's exact
version could not be confirmed in 2026 sources.

| | Bintana | Gambas 3.22 | Lazarus 4.8 / Delphi 13 | Xojo | Qt / .NET | Electron / Tauri |
|---|---|---|---|---|---|---|
| Platforms | Linux (Windows untested) | Linux | All | All | All | All |
| Databases | SQLite | SQLite, MySQL, PostgreSQL, ODBC | Many | Several | Many | npm |
| Data binding | No | Yes | Yes | Partial | Yes | Frameworks |
| Report designer | No (reports in code) | Yes | Yes | Basic | Third party | npm |
| Accessibility | No | Partial | Yes | Partial | Yes | Yes |
| Language | Curated JS, no modules or async | BASIC | Compiled Pascal | Own | C#/C++/Python | Full JS/TS |
| Licence | MIT, free | GPL | GPL/LGPL; Delphi commercial | 499-1999 USD/year | LGPL or commercial | MIT |

- **Gambas is the mirror**: same idea, same Linux niche, twenty years ahead.
  Bintana wins on a language half the world knows, MIT, GTK4, Flatpak,
  correctness and i18n; it loses on databases, binding, visual reports,
  networking and maturity.
- **Lazarus and Delphi set the expectation** for a forms programmer:
  non-visual components, data-aware controls, banded reports.
- **Against Electron/Tauri** the argument is weight and nativeness; it wants
  published numbers (package size, memory).
- **GNOME's tools** (Cambalache 1.0, Workbench, Builder) are good designers with
  no data, reports or VB-style events: they make GNOME apps, not business
  systems. That gap is the niche.
- **Flutter desktop** is now maintained by Canonical: the modern competitor on
  Linux, with no visual designer and no RAD model.
- **Trust signals** a newcomer needs: dated releases, a changelog, Flathub,
  complete examples (clients, invoicing), a forum.
- **Documentation written for an LLM** is a differentiator no classic
  competitor has.

## 7. Order of attack

1. **The cheap fixes**: D1, D2, D3, D4, D5, D7.
2. **R1**: `Database.Postgres` and a cursor for `Query`.
3. **W2**: binding a `Record` to a form, with errors shown on the controls.
4. **W1**: hiding and reordering columns, a filter (cell kinds are answered).
5. **R2**: accessible names, the label relation, mnemonics.
6. **I2 and I4**: non-visual components in the designer; a report designer.
7. **W3**: an editable combo with completion; masked input.
8. **R5**: Windows run on a real desktop.

What the audit found sound and worth keeping as it is: argument refusals
stricter than any competitor's; `Exec` with no implicit shell; XML with no
network or entities; zip refusing escaping names; TLS pinning with resumption
off; exact `Decimal` arithmetic; real threads with `Task`/`Lock`; `Record`
round-tripping JSON, XML (in sequence order) and SQLite; optional dependencies
degrading honestly; the API contract checked against the code; the debugger's
protocol; declarative i18n of prose.
