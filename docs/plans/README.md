# Plans

A plan here is a design argued in prose before it is code: what the application
needed, what was measured, what was rejected on the way and why. Some are built
and kept for the argument; some are waiting for a caller; some have not been
started at all. Each one says which it is in its first lines, and the table
below repeats it, because a plan whose status has to be inferred is a plan that
gets re-argued.

**A plan is deleted when it is built and has nothing left to say.** The rule is
the one `docs/issues/` runs on and `AGENTS.md` states: `docs/http-plan.md` went
that way when its staging landed, with its one live leftover (`Done` sequencing)
already living in `async-plan.md`. A plan kept past its building is a second
description of a feature, written by somebody who did not have it yet. What the
runtime can do is in [`llm/`](https://github.com/getbintana/bintana-llm/blob/main/docs/llm/README.md); git holds what the asking
looked like.

| [task-plan.md](task-plan.md) | **Built**: a class that runs in a thread of its own, plus `Lock`. A first attempt was abandoned for giving the worker a decimal of its own, and the premise under it was false -- `JS_NewClass1` registers a main-runtime class id verbatim in a second runtime, so a worker runs the real `init` functions with the real classes and `rad.js` entire (which is what split `forms.js` off it). **The frontier is callbacks and not writes**, measured: every mutable process-global in a worker's modules is five variables and the rule takes all five. The writes were refused *"until there is a lock"* and that deadline was still wrong -- `File.Save` is atomic, and what concurrency costs is the lost update, a *sequence* no automatic lock reaches; they came back before `Lock` did. `Lock.Hold` is named, recursive, answers nothing, and releases in C because a forced `Stop()` ends a worker mid-statement. Left, with triggers: the catalogue's mutex, and `GCancellable` |
| [interpreter-plan.md](interpreter-plan.md) | **Not started**: what is left to make the interpreter faster after the GCC fix and patches 11-12 (bench 65.5 -> 30.0 s). What was measured and rejected (globals, `-O3`, the rope threshold) and what is out of proportion (NaN-boxing, a JIT) |
| [modules-plan.md](modules-plan.md) | **Stages 0 to 4 built**: a file with `export` is a module (`lib/markdown` first); `import()` and top-level `await` refused (fork patch 13); the explicit `import` resolves a path in the project and a bare name to a `uses` library, and loads a `Task`'s imports into its worker; the IDE completes, outlines, follows, renames and warns by what a module exports (patches 14-15), and a name two modules export used with no import is refused at load (patch 16): a file that keeps its own names. Measured: a helper of the author's silently replaces `lib/markdown`'s `slug`, a `const GAP` stops the program, `lib/qr` prefixes everything by hand, and 221 of the IDE's 280 top-level names are used in one file only. The design is standard syntax with one Bintana rule -- a file with `export` is a module whose exports reach every file **without an `import`**, the rest private; a name two owners export is distributed to nobody and fixed with one standard `import` in the file that uses it. **The precondition is promises**: QuickJS evaluates a module through one, so the intrinsic has to be registered and its global deleted -- which also closes the never-collected class family behind patch 5 and the `import()` abort |
